# BantooBooks Tutorial Content System

This folder is the **single source of truth** for every training and
marketing tutorial about BantooBooks. It is written and structured so it can
be:

1. Read directly by humans (as plain markdown), and
2. Fed into video-generation tooling (Guidde screen recordings, Synthesia AI
   avatar narration) and a future help center, without rewriting the content.

If a feature's UI changes — a button is renamed, a field moves, a workflow
changes — **update the tutorial here first**. Everything downstream (Guidde
projects, Synthesia videos, help center articles) should be regenerated or
re-recorded from this content, not the other way around.

This is a **content/documentation folder only**. Nothing in here is imported
by, or affects, the running application. No videos are generated by anything
in this folder — it only produces the structured content that a human (or a
future automation) would feed into Guidde, Synthesia, or a help-center CMS.

## Folder contents

```
tutorials/
  README.md              This file.
  TEMPLATE.md             Blank template — copy this to start a new tutorial.
  schema.json             Formal JSON Schema for the tutorial frontmatter.
  001-create-a-customer.md
  002-create-a-supplier.md
  003-create-a-sales-invoice.md
  004-record-customer-receipt.md
  005-add-inventory-item.md
```

## Format: markdown + YAML frontmatter

Every tutorial is one markdown file with a YAML frontmatter block at the top
(between `---` markers) followed by a short human-readable body. This format
was chosen deliberately over a pure `.json` or `.yaml` file:

- **Human-readable**: anyone can open the file in Cursor/GitHub and read it
  like a normal document, with a rendered body underneath the data.
- **Machine-parseable**: any YAML frontmatter parser (e.g. `gray-matter` in
  Node, `python-frontmatter` in Python) can extract the structured fields
  in one line, ready to hand to a Guidde/Synthesia integration or a help
  center importer.
- **Diff-friendly**: YAML frontmatter reviews cleanly in pull requests, field
  by field, which matters a lot for a content set that will be edited
  frequently as the product evolves.

The frontmatter is the **source of truth**. The markdown body below it is
optional free-form space for anything that doesn't fit a field (longer
explanations, reviewer notes, embedded screenshots later) — always keep the
frontmatter itself complete and correct even if the body is minimal.

## The schema

[`schema.json`](./schema.json) is a formal JSON Schema (draft-07) describing
every field, its type, and whether it's required. It exists so that:

- A future build/CI step can validate every tutorial file's frontmatter
  automatically (parse YAML → validate against `schema.json`).
- Anyone building a Guidde/Synthesia/help-center integration has an
  unambiguous, versioned contract to code against instead of reverse
  engineering it from examples.

Every tutorial (and `TEMPLATE.md`) **must** include all of these fields:

| Field | Purpose |
|---|---|
| `tutorial_id` | Stable kebab-case id. Must equal the filename minus the `NNN-` prefix and `.md`. Never change once published. |
| `title` | Human-readable title / help-center article title. |
| `feature_area` | Product area (`Customers`, `Sales & Invoicing`, `Payments`, `Inventory`, `Purchasing`, `Banking`, etc. — see `schema.json` enum). |
| `audience` | Who this is for, in plain terms (e.g. "Shop owner / cashier"). |
| `goal` | One sentence: what the user accomplishes. |
| `prerequisites` | What must already be true/set up first. |
| `demo_company` | Which permanent demo org to record in — use `Central Distribution Cameroon SARL` unless there's a specific reason not to. |
| `test_data` | The exact realistic values to type/select while recording. |
| `step_by_step_actions` | Numbered actions, quoting real UI labels exactly. |
| `screen_to_show` | Which page/panel is visible at each step, for a video editor who doesn't know the app. |
| `voiceover_script` | Friendly, plain-language narration, mapped to the steps (assumes the viewer can see the screen). |
| `on_screen_highlights` | What to circle/zoom/emphasize at each step. |
| `expected_result` | Concrete, checkable end state. |
| `short_youtube_title` | Punchy title, <70 chars. |
| `youtube_description` | 2-4 sentences + bullet list, written for discoverability. |
| `help_center_article` | Self-contained written how-to, usable as a standalone help doc. |
| `guidde_recording_notes` | Practical notes for whoever records this in Guidde. |
| `synthesia_script` | Separate ~60-90s narrator script for an AI avatar tool — must stand alone with **no** visual-only references, since the Synthesia viewer may never see the matching screen recording. |

See `schema.json` for exact types, and any of the 5 existing tutorials for
real, filled-in examples of every field.

## Naming convention

Files are named `NNN-slug.md`:

- `NNN` — a 3-digit, zero-padded sequence number (`001`, `002`, …), purely for
  ordering in a file browser. It carries no other meaning — do not renumber
  existing files when adding a new one.
- `slug` — kebab-case, and **must exactly match** the `tutorial_id` field
  inside the file.

Example: `003-create-a-sales-invoice.md` has `tutorial_id: create-a-sales-invoice`.

## How to add a new tutorial

1. Copy `TEMPLATE.md` to a new file named `NNN-your-slug.md`, where `NNN` is
   the next unused number (check the highest existing number in this folder).
2. Fill in **every** field — do not leave placeholder text in the final file.
3. **Ground every field in the real app.** Before writing `step_by_step_actions`
   or any exact label, open the actual page/component/translation file in
   `ledger/` and copy the real button/field text verbatim. Do not paraphrase
   or invent UI labels — a video recorder or Guidde walkthrough will click on
   exactly what you wrote.
4. Use `demo_company: "Central Distribution Cameroon SARL"` and pull
   `test_data` values that match that org's actual seeded style: Cameroonian
   business names (see `ledger/scripts/demo-data.ts`), XAF amounts at
   distributor scale, and real-looking consumer product names from the
   seeded catalog (Coca-Cola, Maggi, Omo, Nescafé, etc. — used only as
   representative demo inventory, per the disclaimer in that file).
5. Validate the frontmatter against `schema.json` (see below) before
   committing.
6. If the tutorial replaces or makes an older tutorial obsolete, don't delete
   the old file outright — flag it for removal in the PR description so a
   human can also retire the corresponding Guidde/Synthesia/help-center
   assets, since those live outside this repo.

### Validating a tutorial file locally

There's no build step wired up yet (this folder is intentionally
dependency-free), but you can spot-check a file's frontmatter with any YAML +
JSON Schema tool, for example with Python:

```bash
pip install pyyaml jsonschema
python3 - <<'PY'
import re, json, yaml, jsonschema

text = open("tutorials/003-create-a-sales-invoice.md").read()
frontmatter = re.match(r"^---\n(.*?)\n---\n", text, re.S).group(1)
data = yaml.safe_load(frontmatter)
schema = json.load(open("tutorials/schema.json"))
jsonschema.validate(data, schema)
print("OK")
PY
```

## How to update tutorials (no coding experience needed)

You don't need to be a developer to keep these tutorials up to date. If you
can edit a text file and run two commands in a terminal, you can do this.

1. **Edit or add a file in `/tutorials`.** Open any of the numbered
   `.md` files (or copy `TEMPLATE.md` to start a brand-new one) and change
   the text. You don't need to touch anything outside this folder.
2. **Open a terminal in the project folder and run:**

   ```bash
   npm run generate:tutorials
   ```

   This reads everything in `/tutorials` and builds a fresh, ready-to-use
   set of files for every tutorial. It only takes a second, it doesn't need
   the internet, and it's completely safe to run as many times as you like.
3. **Run this next, to double-check everything came out correctly:**

   ```bash
   npm run verify:tutorials
   ```

   If you see `ALL CHECKS PASSED` at the bottom, you're done — everything
   generated correctly. If something looks wrong, just re-check your edit
   in step 1 (a common mistake is deleting a `"` quote mark by accident)
   and run both commands again.
4. **Grab your finished files from `/generated/tutorials/<tutorial-name>/`.**
   Each tutorial gets its own folder (e.g. `create-a-customer/`). Here's
   which file to use for what:

   | I want to... | Open this file |
   |---|---|
   | Give a screen-recorder a checklist for Guidde | `guidde.md` |
   | Get a narration script for a Synthesia AI-avatar video | `synthesia.md` |
   | Upload a video to YouTube (title, description, chapters) | `youtube.md` |
   | Publish a written how-to article to the Help Center | `help.md` |
   | Post about it on LinkedIn | `linkedin.md` |
   | Post about it on Facebook | `facebook.md` |
   | Post about it on X (Twitter) | `twitter.md` |
   | Send it in an email newsletter | `email.md` |
   | Make a short vertical video (TikTok/Reels/Shorts) | `shorts.md` |
   | Answer common questions about it | `faq.md` |
   | Get SEO/keyword info for a web page | `seo.json` |

   Every file is plain text — open it, copy what you need, and paste it
   wherever it's going. Nothing here is a video; these are the scripts and
   text that a person (or a video tool) turns into the final video or post.

That's the whole workflow — edit, run two commands, grab your files. See
[`generator/README.md`](../generator/README.md) if you want the technical
details of how each file gets built.

## What this feeds

- **Guidde**: `step_by_step_actions`, `screen_to_show`, `on_screen_highlights`,
  and `guidde_recording_notes` give a recorder everything needed to capture
  and annotate a screen-recording walkthrough without guessing.
- **Synthesia**: `synthesia_script` is a ready-to-paste narrator script for an
  AI avatar video, timed to roughly 60-90 seconds and written to make sense
  with no visible screen.
- **YouTube**: `short_youtube_title` and `youtube_description` are ready to
  paste into a video upload form.
- **Help center**: `help_center_article` is a standalone written how-to that
  doesn't depend on a video existing at all.

No video files, Guidde projects, or Synthesia videos are created by anything
in this repository — this folder only produces the structured content a
human (or a future automation) would feed into those tools.
